# Competitive analysis

**Updated:** 2026-10-10. This is an architectural scan, not a benchmark, penetration test, or feature-by-feature audit. Claims link to upstream project documentation. Unsupported details are marked unknown. DropMesh's differentiator remains a hypothesis.

| Project | Network / security / discovery / relay | Resume, browser, platforms | Lesson for DropMesh |
|---|---|---|---|
| AirDrop | Apple describes BLE discovery, peer-to-peer Wi-Fi, and end-to-end encryption; [Apple security overview](https://support.apple.com/guide/security/airdrop-security-sec2261183f4/web). Relay: not a general Internet relay. | Resume details: unknown. Apple ecosystem. | Pairing simplicity and explicit recipient choice matter; ecosystem constraint remains. |
| LocalSend | Local HTTP(S)/REST over LAN and discovery; optional remote flows are evolving. [Protocol](https://github.com/localsend/protocol), [app](https://github.com/localsend/localsend). | Mobile/desktop support; browser receiver and resume guarantees: verify per version. | Excellent local-first reference. Avoid assuming a novel LAN feature is differentiation. |
| PairDrop | Browser-first WebRTC DataChannels, WebSocket signaling and STUN/TURN. [Upstream](https://github.com/PairDrop-nearby/PairDrop). | Browser/device support; durable resume: unknown. | Browser interoperability is its own product and storage constraint problem. |
| croc | CLI, PAKE, direct connectivity with relay fallback, encrypted transfer. [Upstream](https://github.com/schollz/croc). | Resume, browser, multi-platform clients. | Direct + relay + resume are already solved product capabilities. Compare usability, reliability, and diagnostics. |
| Syncthing | Persistent device identities, discovery and direct connectivity, encrypted relay fallback. [Relaying](https://docs.syncthing.net/users/relaying.html). | Cross-platform; continuous sync rather than one-shot sharing; browser UX not central. | Direct fallback and relay privacy are established patterns; avoid sync complexity in DropMesh MVP. |
| Magic Wormhole | Mailbox exchanges PAKE messages; Transit races direct hints and relay. [Overview](https://magic-wormhole.readthedocs.io/en/latest/welcome.html), [Transit](https://magic-wormhole.readthedocs.io/en/latest/transit.html). | CLI and protocol libraries; browser support unknown. | Use established PAKE designs for short codes; control and bulk data can use separate paths. |
| Tailscale Taildrop | Device sharing in a managed tailnet; direct/DERP connectivity inherits Tailscale. [Docs](https://tailscale.com/docs/features/taildrop). | Platform availability and file limits vary by product release; browser support unknown. | Private-network identity simplifies reachability, but requires a shared network membership. |
| KDE Connect | Paired-device communication on LAN; TLS; file, clipboard, and device-control features. [Upstream](https://github.com/KDE/kdeconnect-kde). | Desktop/mobile ecosystem; browser/resume specifics unknown. | A data bridge needs consent and granular features; do not expand M1 into remote-control scope. |
| Snapdrop | Browser-based local sharing using WebRTC and a signaling server. [Upstream](https://github.com/SnapDrop/snapdrop). | Web clients; large-file/resume guarantees unknown. | Minimal browser UX does not prove reliability for large transfers. |
| WebRTC architectures | ICE connectivity checks, STUN, TURN, DTLS/SCTP DataChannels. Pion supports these components. [Pion WebRTC](https://github.com/pion/webrtc). | Native/browser interop is possible with signaling and implementation constraints. Resume/storage are application responsibilities. | Reuse ICE rather than recreating it if WAN/browser goals justify the dependency. |
| QUIC transfer systems | QUIC offers encrypted multiplexed streams; implementations differ. No exact comparator selected yet. | Platform/library constraints need versioned experiments. | Compare real direct paths; QUIC does not itself solve NAT rendezvous or relay. |
| libp2p | Modular transports, identity, discovery, NAT traversal and relay options. [Project](https://libp2p.io/). | Go and browser ecosystems; file-transfer UX/resume varies by application. | Evaluate full-stack reuse against operational and dependency complexity before custom signaling. |

## Positioning

Do not claim DropMesh is unique at transferring directly, relaying, resuming, or supporting browsers. Test the narrower hypothesis that operators value an auditable Go transfer core, accurate route/outcome reporting, and restartable large transfers with strong filesystem safety. Discovery, cross-platform UX, and WAN support remain separate product gates.
