# Current state

**Evidence updated:** 2026-10-13. **Status:** M0 foundation is implemented. M1 behavior has local Windows loopback evidence but its physical LAN and hosted acceptance gates remain open. M2 implementation is in progress and does not close M1's external gates.

## Implemented and locally verified

- Go module `dropmesh`, provisional product name, pinned Go 1.27.2 and quic-go v0.63.0; local PowerShell bootstrap and cache scripts.
- Fresh PowerShell bootstrap extraction from the official Go ZIP passed SHA-256 verification; the extracted toolchain reported go1.27.2 and passed `go test ./...` and `go vet ./...`.
- One CLI executable with `send`, `receive`, `resume delete`, invite stdin, `--yes`, size limit, version, progress, cancellation exit handling, and usage errors.
- Protocol v2 invite prefix/version, control version, and ALPN. Every sender process creates a fresh one-use invite; a stable random 128-bit transfer ID is distinct from the invite session and can be explicitly supplied with `send --resume`.
- Receiver consent is required on every resume. The receiver returns a bounded, exact-length bitmap representing its committed chunk prefix; sender and receiver reject non-prefix, out-of-range, duplicate, descending, malformed, or missing chunks.
- Receiver state uses rooted `<output>/.dropmesh-state/<transfer-id>/` data and journal files, a per-output-directory OS lock, data-sync-before-journal-sync commits, CRC32C torn-record detection, 24-hour idle expiry, and explicit deletion.
- Recovery scans the bounded descriptor header and fixed-size records, re-hashes committed data, truncates invalid tails, and retransmits bytes lacking a valid record. Full-file mismatch resets the commit journal so a subsequent run can retransmit rather than remain permanently stuck.
- Final output uses rooted hard-link no-clobber publication. A matching pre-existing destination is accepted idempotently after full digest verification; different bytes are preserved and rejected.
- M2 tests cover store commit/reopen, journal tail truncation, modified committed bytes, whole-file mismatch reset, state mismatch, lock contention, one-state limit, expiry, deletion, empty-file publication, no-overwrite, injected short writes/data and journal sync failures/disk-full, malformed duplicate/descending/already-committed/missing/corrupt chunks, and process exit between data write/sync, record write/sync, and publication cleanup.
- Real QUIC and child-process CLI tests cover initial v2 transfer and restarted sender/receiver pairs resuming from committed chunks with a fresh invite and matching final bytes. The CLI test kills both endpoint processes after receiver commit and confirms the second run sends only the remaining chunks.
- Existing M1 unit/integration coverage includes invite bounds/expiry, wrong secret, certificate substitution, replay, concurrent admission, four-slot saturation, malformed frames/chunks, source mutation, size refusal, cancellation, backpressure, and cleanup.
- Fresh Windows/amd64 verification on 2026-10-11: `go test ./... -count=1`, `go test -race ./... -count=1`, `go vet ./...`, gofmt check, five parser fuzz smokes (2 seconds each), and cross-builds for linux/amd64, linux/arm64, windows/amd64, darwin/amd64, and darwin/arm64 pass. ## Not yet verified or accepted

- M2 is not accepted. Remaining: hosted/native process-crash/fault matrix on macOS and Linux; independent protocol/threat-model review; and final acceptance matrix review.
- Process exit tests prove restart recovery from tested local Windows conditions and Linux Docker overlay conditions, plus simulated storage faults. They do not prove power-loss, controller-cache, or directory-entry durability; hosted/native platform crash-fault acceptance remains open.
- Physical LAN transfer between two devices with Internet unavailable, including cancellation and bounded-resource evidence, has not run.
- Hosted Windows/Linux/macOS native CI has not run. Linux race and pinned Staticcheck passed in containers; Windows race passed locally.
- Cross-builds from Windows do not establish runtime behavior on Linux or macOS. Hard-link support and OS-lock semantics need native runs.
- Injected storage failures are covered, but physical device disk-full/write-fault behavior is still unverified. M1 hard-link publication still fails closed where hard links are unsupported.
- Refreshed govulncheck found no vulnerable symbols or imported packages, but still reports uncalled module-level GO-2026-5932 for `golang.org/x/crypto/openpgp`; it has no fixed version. The scanner reports no project OpenPGP import.
- No repository publication or release exists. DropMesh name conflicts with other uses; maintainer, private security, and conduct-enforcement contacts remain unresolved.
